# Как пользоваться ботом ModuleDev

Production-бот курса: [@module_internship_bot](https://t.me/module_internship_bot).

Через бота участник регистрируется на курсе, узнаёт код открытого задания,
сдаёт ссылку на работу, получает результат проверки и запрашивает наставника.

## Быстрый старт

1. Убедитесь, что у Telegram-аккаунта установлен публичный username.
2. Откройте [@module_internship_bot](https://t.me/module_internship_bot).
3. Нажмите **Start** или отправьте:

   ```text
   /start
   ```

4. Дождитесь ответа `Регистрация подтверждена.`
5. Посмотрите открытые задания:

   ```text
   /assignments
   ```

Если бот отвечает `Пользователь не найден в активном списке курса.`,
отправьте куратору свой текущий Telegram username. Не создавайте новую учётную
запись без согласования.

## Регистрация после открытия задания

Команду `/start` можно отправить в любой момент. Если задание уже открыто,
поздняя регистрация не создаёт повторное уведомление об открытии, но участник
всё равно может сдать работу до дедлайна.

Дедлайны бот показывает по московскому времени с пометкой `МСК`.

## Как сдать работу

Код задания указан в уведомлении об открытии и в ответе на `/assignments`.

Формат команды:

```text
/submit <код> <url>
```

Пример:

```text
/submit week1 https://github.com/example/private-solution/commit/0123456789abcdef0123456789abcdef01234567
```

Требования к ссылке:

- используется абсолютная ссылка с `https://` или `http://`;
- ссылка ведёт на работу в формате, указанном в задании;
- GitHub-аккаунту `psilon2000` (`psilon2000@mail.ru`) заранее предоставлен
  доступ на чтение к приватному репозиторию;
- ссылка однозначно указывает на проверяемую версию работы;
- в сообщении нет токенов, паролей и других секретов.

После успешной сдачи бот отвечает `Ссылка принята.` Работа появится у
проверяющего автоматически.

Для одного задания участник самостоятельно отправляет ссылку только один раз.
Если отправлена неправильная ссылка, сообщите куратору: он может заменить её
административной командой до готовности проверки.

## Результат проверки

После завершения проверки бот отправит результат отдельным сообщением.
Результат также можно запросить вручную:

```text
/result <код>
```

Пока проверка не завершена, бот отвечает `Результат не найден.`

Результат содержит:

- итог проверки;
- вердикт;
- комментарий проверяющего;
- PDF с обратной связью.

## Повторная проверка

После готовности первой проверки можно один раз запросить проверку нового commit:

```text
/recheck <код> https://github.com/<owner>/<repo>/commit/<40-символьный-SHA>
```

Требования:

- используется только HTTPS URL GitHub commit с полным 40-символьным SHA;
- query, fragment, сокращённый SHA и ссылка на branch не принимаются;
- commit должен отличаться от первой сдачи;
- повтор разрешён после дедлайна и после закрытия задания;
- для одного задания доступна ровно одна повторная проверка.

Результат повтора доступен по `/recheck-result <код>`. В меню Telegram
используется эквивалентная команда `/recheck_result <код>`.

Первая проверка остаётся официальной. Повтор не меняет её балл, вердикт,
комментарий и файлы. Команда `/result` всегда возвращает первую проверку.

## Наставник

Запросить наставника можно после готовности проверки:

```text
/mentor <код>
```

Один раз можно запросить другого наставника:

```text
/mentor change <код>
```

Если проверка ещё не готова, бот не назначит наставника.
Если повторная проверка уже готова, новый наставник получает её внутренний PDF.
Уже назначенный наставник получает отдельное уведомление после подтверждения
результата повтора.

## Остановка и повторный запуск

Чтобы отключить привязку Telegram-аккаунта и новые уведомления, отправьте:

```text
/stop
```

Сданные работы и результаты при этом не удаляются. Для повторной регистрации
отправьте `/start`.

Если результат был готов во время остановки, после повторного `/start` бот
может доставить его автоматически. Результат также доступен по команде
`/result <код>`.

## Все команды участника

| Команда | Назначение |
| --- | --- |
| `/start` | Зарегистрироваться или восстановить регистрацию |
| `/stop` | Отключить привязку и уведомления |
| `/help` | Показать краткую справку |
| `/assignments` | Показать открытые задания и дедлайны |
| `/submit <код> <url>` | Сдать ссылку на работу |
| `/result <код>` | Получить готовый результат проверки |
| `/recheck <код> <github-commit-url>` | Один раз запросить повторную проверку |
| `/recheck-result <код>` | Получить результат повторной проверки |
| `/mentor <код>` | Запросить наставника после проверки |
| `/mentor change <код>` | Один раз сменить назначенного наставника |

## Типовые ответы

- `У Telegram-аккаунта должен быть корректный username для регистрации.`
  Установите Telegram username и повторите `/start`.
- `Пользователь не найден в активном списке курса.` Передайте куратору
  текущий username.
- `Сдача доступна только зарегистрированному активному обучающемуся.`
  Выполните `/start`; если не помогло, обратитесь к куратору.
- `Задание не найдено.` Проверьте код через `/assignments`.
- `Укажите корректные код задания и абсолютную http/https ссылку.` Проверьте
  формат `/submit <код> <url>`.
- `Сдача уже принята либо задание закрыто или просрочено.` Проверьте дедлайн;
  для замены принятой ссылки обратитесь к куратору.
- `Результат не найден.` Дождитесь завершения проверки.
- `Повторная проверка пока недоступна.` Дождитесь включения функции куратором.
- `Повторная проверка ещё не готова.` Дождитесь отдельного уведомления.

Если проблема не описана выше, отправьте куратору текст ответа бота, код
задания и свой Telegram username. Не пересылайте токены и другие секреты.
